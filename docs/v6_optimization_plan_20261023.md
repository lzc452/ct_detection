## 1. 根因分析

先立一条筛选标准：**"根因"必须是"如果不改它，同类问题还会以别的形式再犯"的东西**。只解释这次为什么差 0.02 的，是原因；会让下一次换个姿势再摔的，才是根因。

按这个标准筛出 6 条，分两层。

### 1.1 技术层根因

#### R1 用"全局预处理"去解"局部瓶颈"，必然用两类损失换一类收益

**判据**：一次干预只改变了输入表示，而三类目标的瓶颈向量不同 —— 那么任何全局变换在瓶颈维度上都是单调的，必然有赢有输。

**证据**：ΔmAP 可以精确拆开，`(−0.055 −0.038 +0.030)/3 = −0.0209`，与实测逐位吻合。三类瓶颈不同：

| 类别 | 框数 | 形状 | 瓶颈 | ROI 放大 1.55× 的效果 |
|---|---|---|---|---|
| 亮斑 | 901 | 圆 1.07 | 分辨率 | ✅ +0.030 |
| 暗斑 | 1560 | 圆 1.10 | 与纹理的可分性 | ❌ −0.038 |
| 损伤 | 484 | 长条 **4.13** | 上下文 + 定位容差 | ❌ −0.055 |

**不改会怎样**：下次还会有人提"再放大一点""再裁紧一点"，因为它在亮斑上确实有效。

**对策**：任何全局预处理改动，**先把三类目标的瓶颈写出来并对齐方向**；只要有一类方向相反，就必须引入"按类别分路"的机制（分层采样、级联、多尺度），而不是继续调全局参数。

#### R2 ROI 的定义里没有「上下文」这一项，贴边是数学后果不是意外

**判据**：ROI 边界 = 标注框外包络 + 固定 2.5% 余量。这是一个**包含式约束**（保证框在内），不是一个**距离约束**（保证框周边看得到 N 个像素）。包含式约束下，"长条状目标贴边"是必然结果。

**证据**：损伤框到最近 ROI 边界的距离 < 自身半长边的比例 **9.7%**；暗斑 0.1%、亮斑 0.0%。损伤长宽比 4.13，是唯一的长条目标。

**不改会怎样**：换成"椭圆 ROI""多边形 ROI""按电芯区域切"，只要定义里还是"包住框"，贴边问题原样复发。

**对策**：边界定义改成 `margin = max(k · 目标长边, c)`，把"周边可见范围"写成显式约束项。

#### R3 成像质量差 4 倍的样本，共用同一套预处理参数

**判据**：同一条归一化边界，在高分辨率图上插值 2.40×、在低分辨率图上 **10.20×**（面积），差 4.3 倍。同一套参数对两类样本的信息破坏程度不在一个量级。

**证据**：
- 2129×1198（67.9%）→ ROI 647×991 → 放大 2.40×
- 1052×582（20.8%）→ ROI **319×481** → 放大 **10.20×**
- 对照 V5 全图：1052×582 只放大 3.33×

**不改会怎样**：任何"固定画布 + 固定裁剪比例"的方案，都会对小图产生插值放大，且越裁越严重。

**对策**：预处理按原生分辨率**分桶**。小图要么不放大（用更小画布），要么先超分再裁，要么直接走全图分支。

#### R4 损伤类的样本量根本不够，且高度分散（本轮新发现，可能是最深的一条）

**判据**：样本量决定上限。若某类的"电芯级"样本少到无法覆盖分布，任何模型改动都只是在拟合那少数几颗电芯。

**证据**：

| 类别 | 框数 | 占框比 | mAP 权重 | 每框相对权重 |
|---|---|---|---|---|
| 暗斑 | 1092 | 53.0% | 1/3 | 0.63 |
| 亮斑 | 630 | 30.6% | 1/3 | 1.09 |
| **损伤** | **338** | **16.4%** | 1/3 | **2.03** |

更要紧的是分布：
- 含损伤的训练图只有 **307 张 / 3195 = 9.6%**
- 这 307 张散在 **129 个分组（电芯）** 上，**中位每组只有 2 张**，最多 13 张
- 含损伤的分组只占全部训练分组的 14%

**这意味着**：模型要靠"每颗电芯 2 张图"学会识别划痕，然后泛化到完全没见过的电芯。混淆矩阵里 True=damage 的正确率即使放到 conf=0.001 也只有 **0.49** —— 一半的损伤根本没有任何一个框能匹配上，这个天花板很可能主要由数据决定。

**不改会怎样**：所有针对损伤的模型侧改进（加权、过采样、换 head）都会很快撞到这个天花板，然后被误判为"方法无效"。

**对策**：把"损伤数据采集/标注"提升为与建模同等优先级的任务；模型侧用分层采样做**有限补偿**（上限受 129 个电芯限制，不能指望翻倍）。

### 1.2 方法论层根因

#### R5 实验纪律缺失，错误结论存活了 3 轮

**判据**：8 次训练里只有 1 次（V5 vs V5.2）是干净的单因素对照。其余都同时改了 2~5 个变量，或者参照物本身有病。

**证据**：
- V5.1-A 同时改 imgsz + 4 项增强 → 无法归因
- V5.1-A 严重过拟合（val box loss 是 train 的 2.0 倍）却被当作参照物 → 得出"ROI 有效 +0.0554"
- 该结论存活约 24 h，直到 V5.2 单因素对照才被推翻
- 另一条"损失来自关增强"也在同一时刻被证伪

**不改会怎样**：每轮都在上一轮的错结论上叠加实验，越跑越远，而且**浪费的不是算力，是判断力**。

**对策**：预注册（`DECISIONS` D-003）+ 单因素（`LESSONS` L-008）+ 结论台账（`FINDINGS`）。已落地，见 §8。

#### R6 评测口径分散，指标之间互相矛盾时没有裁决规则

**判据**：同一模型在不同口径下能得出相反结论时，必须有"哪个说了算"的事先规定，否则就是挑数字。

**证据**：
- 层 1（`model.val`）与层 2/3（`predict`）口径不同，V5 在两者下差 0.0108
- 组级漏检分母曾用图片数 389，正确是分组数 170
- 电芯级漏检抽样 n=10，±1 颗 = ±10pt
- V5.2 的 mAP"更差"只有 0.9σ，但 FP/漏检/损伤召回三项一致更差

**对策**：三层指标体系 + **选型只看层 2/3**（`DECISIONS` D-005）；n<100 的切片只作方向参考（`LESSONS` L-015）。

## 2. 把"准确率高且鲁棒性强"变成可测量的东西

没有这节，目标就是口号。五个维度，前两个已有数据，后三个需要新建。

| # | 维度 | 定义 | 当前实测 | 目标 |
|---|---|---|---|---|
| 1 | 准确率 | 层 2/3：mAP50-95、FP/千张、组级漏检、损伤召回 | 0.4186 / 88.8 / 26.47% / 0.562 | 全面不低于现役，其中至少两项改善 ≥10% |
| 2 | **分辨率鲁棒性** | 两个分辨率桶的指标差（高 vs 低） | 损伤 R 差 **0.148**（0.519 vs 0.667）、FP 差 11.0 | 差距缩小到 ≤0.08 |
| 3 | **分组鲁棒性** | 按电芯分组，取**最差 20% 组**的召回（不是平均值） | **未测** | 最差 20% 组召回 ≥0.45 |
| 4 | **成像扰动鲁棒性** | gamma ±20%、对比度 ±20%、高斯噪声 σ=3、JPEG q=70 后的指标衰减 | **未测** | 任一扰动下 mAP 衰减 ≤8% |
| 5 | **标注抖动鲁棒性** | GT 框随机抖动 ±2 px 后重算指标 | **未测** | 衰减 ≤5%（超过说明模型对框边界过拟合） |

第 3~5 项当前是空白。**"鲁棒性强"目前没有证据**，这一点必须写清楚 —— 不能拿"在 676 张上表现还行"当鲁棒性。

> 为什么第 2 项用"两个桶的差距"而不是绝对值：产线上两种相机同时存在，模型不能只对一种好用。这是本产线的特殊约束。

## 3. 方案选型

### 3.1 三个候选

| 维度 | **A：全图基线 + 损伤专项** | **B：带余量裁剪 + 分辨率分桶** | **C：全图主检 + 损伤二次切片** |
|---|---|---|---|
| 做法 | 保持 V5 的 1920 全图；只做类别分层采样 + 损伤定向增强 | ROI 外扩 `k=1.5×损伤长边`；小图分桶；叠加分层采样 | 全图先检；对疑似损伤区域裁 512 切片做二次精检 |
| 上下文 | 完整 | 恢复约 90%（横向 +30%） | 完整 |
| 分辨率 | 亮斑 15.1 px | 亮斑 22.2 px（仍比 V5 高 47%） | 切片内损伤放大 2~3× |
| 单张时延 | 13.4 ms | ~10.4 ms（画布不变） | 18~22 ms（两次推理 + 融合） |
| 训练成本 | 3.3 h/轮 | 2.2 h/轮 | 3.3 h + 切片模型 2.2 h |
| 工程量 | **小**（1 天） | **小**（改 1 个常量 + 重新物化，0.5 天） | **大**（3~5 天，含 NMS 融合与回映射） |
| 主要风险 | 损伤数据天花板（R4）不动 | 亮斑增益缩水；低分辨率图仍 7.3× 插值 | 级联误差、时延、维护成本 |
| 依赖 | 无 | 需重跑全部评测 | 需两套权重 + 部署改造 |

**关键计算（B 为什么便宜）**：画布固定 1536，ROI 从 647×991 扩到 841×1154 后，缩放率从 1.550 降到 1.331。**算力不变（画布没变），单轮仍是 97 s**。等于用"放大倍率"换"可见范围"，而放大倍率本来就有富余（亮斑 22.2 px 仍远高于 V5 的 15.1 px）。

| | 纯 ROI（现状） | 带余量 k=1.5 | V5 全图 |
|---|---|---|---|
| ROI 尺寸（2129 图） | 647×991 | **841×1154** | 2129×1198 |
| 缩放率 @1536 | 1.550 | 1.331 | 0.81 @1920 |
| 亮斑像素 | 26.0 | 22.2 | 15.1 |
| 面积占原图 | 25.1% | **38.1%** | 100% |
| 单轮耗时 | 97 s | ~97 s | 149 s |

### 3.2 推荐路径

**不选 C，也不只选 A。走 A → B 的顺序，用 Gate 决定是否升级到 C。**

理由：
1. **B 的成本几乎为零**（改一个常量 + 2.2 h 一轮），却能直接检验根因 R2。这是全项目性价比最高的一次实验。
2. **A 是 B 的对照组**，不是替代关系。B 若失败，A 的基线数据仍然有效。
3. **C 只有在 A、B 都证明"损伤瓶颈是分辨率+上下文"之后才值得做**。若 R4 成立（瓶颈是数据量），C 会白做 5 天。

**明确不做的事**（已被证伪，见 `FINDINGS`）：
- ❌ 继续调 ROI 画布（1536 → 1408/1792）：F-013 已说明没有消融依据
- ❌ 继续调增强（mosaic/degrees/erasing）：F-005 已单因素否定
- ❌ 用 V5.1-A 当任何参照物：F-001 已证伪

## 4. 执行步骤与优先级

排序依据：**每 GPU 小时能回收多少"可验证的判断"**。P0 两项都是"不改模型，只改认知"的，因为它们决定后面所有投入是否有意义。

### P0-1 损伤标注一致性审计（0 GPU · 0.5 天）★ 最高优先

**为什么第一**：损伤 AP 上限只有 0.49。如果这里面有一半是标注本身模糊造成的，那么后面所有针对损伤的建模投入都是在优化一个测不准的目标。这一步不做，后面全是赌博。

**做法**：
1. 从 129 个含损伤分组里分层抽 25 颗电芯，取 100 个损伤框
2. 同一批图由第二个人**独立重标**（不看原标注）
3. 计算：标注间 IoU 分布（中位 / p10）、框宽差分布、**"两人是否都认为这是损伤"的一致率**
4. 同时统计：跨框宽 <5 px 的比例（IoU≥0.5 的容差临界）

**判定（Gate G1）**：
- 标注间 IoU 中位 **≥0.75** → 标注可信，进 P0-2（瓶颈在模型/预处理）
- 中位 **0.65~0.75** → 标注有噪声，需在训练目标上放宽（如降低 cls 增益或引入框不确定性）
- 中位 **<0.65** → **停止一切模型侧优化**，先修标注规范。此时 0.49 的上限主要是标注造成的

**产出**：`reports/audit/damage_label_agreement.json`

### P0-2 带余量裁剪单因素实验（2.2 h GPU · 0.5 天开发）

**为什么第二**：直接检验 R2，成本一轮训练，且画布不变所以算力不变。

**做法**：
1. `core/roi.py` **新增** `roi_box_padded(W, H, k)`，不动现有 `roi_box`（历史结果必须可复现）
2. `scripts/materialize_roi_dataset.py` 加 `--margin-k 1.5`，生成 `datasets_v51/CT_DATASET_V51_ROI_M15`
3. 其余超参与 V5.2 **逐项一致**（`args.yaml` diff 只允许出现数据路径）
4. 训练 + 全套评测（eval / sweep / by_resolution / scaleup）

**判定（Gate G2）**：
- 损伤召回 **≥0.52** 且 mAP50-95 **≥0.4186** 且 FP **≤88.8** → B 成立，进 P1-2 定型
- 损伤召回回升但 FP 恶化 → 说明暗斑问题独立，转 P1-1
- 损伤召回没动（仍 <0.47）→ R2 被证伪，损伤瓶颈不在上下文，转 P2 或回到 R4

**必须同时预注册**：这条实验的判据要在训练启动前写进 `FINDINGS` 的 `待验` 条目，训练后改状态。

### P1-1 损伤分层采样（2.2 h GPU · 0.5 天开发）

**为什么 P1**：R4 的补偿手段，但上限受 129 个电芯约束，不能指望翻倍。

**做法**：物理硬链接过采样（不用 txt 列表，避免 ultralytics 的重复条目行为未验证）

- 含损伤图 307 张，重复 ×4（额外 921 张），使含损伤图占比 9.6% → **27.8%**
- 总样本 3195 → 4116，单轮 +29%（97 s → 约 125 s）
- 磁盘代价：硬链接，≈0

**风险**：过采样会让模型对那 307 张过拟合。必须同时看**分组鲁棒性**（最差 20% 组召回），不能只看总召回。

**判定**：损伤召回 +0.03 以上且组级漏检不恶化 → 保留；否则回退。

### P1-2 分辨率分桶（2 h 开发 + 2.2 h GPU）

**为什么 P1 而不是 P0**：影响面只占 test 的 11%（71 张），但 train 占 32%，所以训练侧值得做、评测侧无法验证。做它主要是为了**不浪费三分之一的训练算力**。

**做法**：低分辨率图（1052×582 系列）不放大到 1536，而是：
- 方案 i：单独用 1024 画布训练一个分支（工程量大）
- 方案 ii：低分辨率图走全图 @1536（不裁剪），因为它本来就小，ROI 后只剩 319×481
- 方案 iii：先 2× 超分再裁（引入超分模型，风险高）

**建议先做方案 ii**，改动最小：物化时对 `min(W,H) < 800` 的图不裁，直接全图缩放。这与"带余量裁剪"可叠加。

### P2 损伤二次切片级联（仅当 G1/G2 都通过才启动，3~5 天）

只在前两步证明"上下文 + 分辨率确实是瓶颈"后才做。设计要点：
- 切片只在**第一次推理出现损伤候选**（conf>0.15）时触发，避免全图切片
- 切片尺寸 512，在 1920 图上以候选框为中心取，缩放 3.75×
- 两次结果用 IoU 0.3 融合，类别以二次结果为准
- 时延预算：18~22 ms，需先在产线节拍上确认可接受

### P2-2 鲁棒性测试套件（1 天开发，0 GPU）

把 §2 的第 3~5 项做成可重复执行的脚本，纳入每次模型验收的固定流程。**没有这个，"鲁棒性强"永远只是一句话。**

| **P0-2** | 带余量裁剪 | 2.2 h | 0.5 d | R2 | 损伤 R≥0.52 且 mAP≥0.4186 |

### 5.1 带余量 ROI 边界（P0-2）

在 `core/roi.py` **新增**，不改 `roi_box`：

```python
# 损伤框长边中位数（在高分辨率 2129x1198 的原生图上测得，ROI 坐标 64.6px）
DAMAGE_LONG_SIDE_PX = 64.6
REF_WIDTH = 2129.0          # 上面这个数的测量基准宽度

def roi_box_padded(W, H, k=1.5):
    """带上下文的 ROI：在当前 ROI 基础上各向外扩 k×损伤长边。

    与 roi_box 的区别：
        roi_box         —— 包含式约束（保证标注框在画面内）
        roi_box_padded  —— 距离约束（保证标注框周边至少 k×长边 的可见范围）

    实测依据：纯 ROI 下有 9.7% 的损伤框到边界的距离 < 自身半长边，
    即那一侧的画面已在框外，模型看不到"正常的极片表面长什么样"。
    """
    x0, y0, x1, y1 = roi_box(W, H)
    pad = int(round(k * DAMAGE_LONG_SIDE_PX * W / REF_WIDTH))
    return (max(0, x0 - pad), max(0, y0 - pad),
            min(W, x1 + pad), min(H, y1 + pad))
```

实测结果（`k=1.5`）：

| 原生 | 纯 ROI | 带余量 | 缩放率 | 亮斑 | 面积占比 |
|---|---|---|---|---|---|
| 2129×1198 | 647×991 | **841×1154** | 1.550 → 1.331 | 26.0 → 22.2 px | 25.1% → 38.1% |
| 1052×582 | 319×481 | 415×561 | 3.193 → 2.738 | — | 25.1% → 38.0% |

> 注意：ROI 在 **y 方向本来就接近满高**（0.1181~0.9446 占 83%），外扩空间很小；增益主要在 **x 方向**（0.32~0.62 只占 30% 宽）。所以 `k` 的收益上限由 x 方向决定。

```python
# scripts/oversample_damage.py 核心逻辑
import os, csv, shutil

def build(data_root, manifest, split="train", times=4):
    """把含损伤的图硬链接重复 times-1 次，其余原样链接。"""
    rows = [r for r in csv.DictReader(open(manifest, encoding="utf-8-sig"))
            if r["split"] == split]
    dst_img = os.path.join(data_root, split, "images")
    dst_lbl = os.path.join(data_root, split, "labels")
    n_extra = 0
    for r in rows:
        has_dmg = int(float(r["n_damage"] or 0)) > 0
        reps = times if has_dmg else 1
        for i in range(reps):
            stem = r["name"] if i == 0 else "%s_os%d" % (r["name"], i)
            for src_dir, ext in ((r["src_path"], os.path.splitext(r["src_path"])[1]),):
                link_or_copy(src_dir, os.path.join(dst_img, stem + ext))
            lbl = os.path.splitext(r["src_path"])[0]  # 由调用方换成 labels/*.txt
            link_or_copy(lbl, os.path.join(dst_lbl, stem + ".txt"))
            n_extra += (i > 0)
    return n_extra
```

预期：含损伤图占比 9.6% → **27.8%**（307×4 = 1228 张），总样本 3195 → 4116，单轮 97 s → 约 125 s。

## 8. 训练经验记录机制

### 8.1 为什么不是"再写一个文档"

之前的问题不是"没记录"，而是记录了但**用不上**：
- `experiments/<run>/04_report.md` 有数字，但结论散在各文档
- 坑写在 commit message 和对话里，下次开训练想不起来
- **最贵的**：一条被推翻的结论（F-001）在报告里还留着原文，下一个人会直接引用

所以机制要解决三件事：**可写入、可检索、训练前自动提醒**。

### 8.2 三个文件，各管一件事

| 文件 | 内容 | 关键约束 |
|---|---|---|
| `experiments/LESSONS.md` | 踩坑库，18 条 | 每条必须有 现象/根因/解法/证据；**根因要写到机制层**，不写"我没注意" |
| `experiments/FINDINGS.md` | 结论台账，15 条（含 3 条已证伪） | **已证伪的永不删除**，且必须写"推翻依据"。引用任何结论前先看状态 |
| `experiments/DECISIONS.md` | 决策日志，8 条 | 每条必须写**复核触发条件**：什么变了就该重新讨论 |

分工逻辑：
- 想知道"这个报错见过没" → `LESSONS`
- 想知道"这个结论还能不能引用" → `FINDINGS`
- 想知道"当初为什么这么定" → `DECISIONS`

### 8.3 CLI：让记录成本降到一次命令

`scripts/kb.py`（纯标准库，无第三方依赖）：

| 命令 | 作用 |
|---|---|
| `add-lesson` | 按标签插到对应小节，编号自动取最大 +1 |
| `add-finding` | 按状态插到对应小节；`已证伪` 自动加删除线 |
| `add-decision` | 追加到决策日志 |
| `query <kw>` | 三个文件全文检索，命中条目整块打印 |
| `list --type/--status` | 列条目摘要 |
| `check` | 格式校验：编号重复、缺必填字段、状态非法、**已证伪缺推翻依据** |
| `preflight` | 训练前自检（见下） |

### 8.4 preflight：机制真正生效的地方

`runtime/python.exe scripts/kb.py preflight --data <data.yaml> --imgsz 1536` 会打印：

```
[1] 数据集：类别、train/val 张数、框数、负样本比例、框每图
[2] ROI 一致性：由数据集名推断 roi=，并与已有 run 的 meta 对比（不一致 → 报错退出）
[3] 画布：MP 数、32 对齐检查、ROI 下画布是否超出已验证范围
[4] 与本次训练相关的坑：按标签筛出 11 条标题
[5] 已证伪结论：3 条，禁止当依据
```

这是把"经验"从被动查阅变成**主动拦截**的那一步。只要养成开训练前跑一次的习惯，L-003（meta 写错）和 F-001（引用已证伪结论）就不会再复发。

### 8.5 与现有流程的挂接

```
预注册判据         → FINDINGS.md（状态=待验）
      ↓
kb.py preflight    → 数据集/画布/meta 检查 + 相关坑 + 禁止引用的结论
      ↓
train_run.py       → 训练结束自动 archive_experiment.py → experiments/<run>/
      ↓
全套评测            → reports/eval/*.json
      ↓

      ↓
新踩的坑           → LESSONS.md
```

`AGENTS.md` 已加一节指向这套机制，新会话/新同事从那里进来。
