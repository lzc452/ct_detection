二、业务痛点与建设必要性

（一）业务现状与瓶颈
CT检测是判定电池内部缺陷的核心工序。由于我司产品型号众多，CT照片数据量巨大，缺陷识别目前仍以人工判片为主，存在以下瓶颈：
1. 效率低：人工判片约 ≥5 秒/张，以马安园区年约 550 万张测算，相当于约 954 个人天的判片工作量；
2. 准确率波动大：人员疲劳、经验差异导致误检、漏检；
3. 判定标准难统一：不同人员对同一缺陷的判定尺度不一致，质量波动大；
4. 经验无法沉淀：判片经验依附于个人，人员流动即流失，无法复用。

（二）集团 AI 战略匹配
本课题契合集团"降本增效""流程自动化""数据资产复用"三项核心目标：以 AI 替代重复性判片劳动（降本增效），检测-统计-报表流程自动化（流程自动化），将人工判片经验固化为可持续迭代的模型资产（数据资产复用）。

（三）不落地的负面影响
判片人力投入随产能持续攀升；人工判定波动带来的质量风险长期存在；竞品及行业数字化窗口期错失。

（四）切入点与当前进展
以判定标准较为严格的钢壳出样为切入点，从数量最多、需求最强烈的正面图像先行开发。采用预学习模型迁移训练，对卷绕电芯同样有效，未来可向更多型号、更多方向（X、Y）拓展。
当前进展：Web 端检测系统已完成开发并投入试点使用，首版模型完成训练上线（当前缺陷识别 mAP50 82%，其中暗斑 89.5%、亮斑 74.6%），样本持续收集迭代中，向考核指标（≥95%）推进。

三、AI 建设整体方案（技术 / 产品选型）

（一）解决方案概述
本课题为自主研发：基于深度学习目标检测技术，用我司真实 CT 图像做迁移学习，训练专用缺陷识别模型，并封装为浏览器访问的 Web 系统。业务人员无需安装软件，打开网页上传 CT 照片，即可自动获得缺陷类型、位置、数量结果，并可导出 Excel 报表。
- 模型/工具：YOLOv8 目标检测模型（预训练迁移学习，识别裂纹/暗斑/亮斑三类缺陷）；PyTorch 深度学习框架；OpenCV 图像处理
- 搭建场景：钢壳出样正面 CT 图像的快速筛选（数量最多、需求最强烈的环节先行切入）
- 业务流程改造逻辑：人工逐张判片 → AI 初筛 + 人工复核。检测标准通过模型与阈值固化，消除人员判定差异；漏检/误检样本回收再标注，形成"使用—纠错—重训"的持续迭代闭环，模型越用越准

（二）落地范围（分试点、推广两阶段）
- 试点阶段（当前）：研发体系钢壳出样业务，覆盖判片/质检岗位，正面 CT 图像
- 推广阶段：扩展至更多产品型号及 X/Y 方向图像，逐步推广至其他 BU
- 系统对接：按数据安全要求，系统独立运行于内网专用电脑，暂不对接 ERP/MES 等系统，检测数据不出内网；预留标准数据接口，未来可按需对接

（三）平台/产品选型理由
- 对比采购商业机器视觉软件：商业软件按工位授权、费用高，算法封闭、无法针对我司缺陷定制训练；本方案内部自用零授权费用，模型用自有数据训练，产品更新后可自主迭代
- 对比云端 AI 服务：CT 图像属敏感数据，云端方案存在外泄风险且按调用量持续计费；本方案完全私有化、离线运行，无持续调用费用
- 交付周期：系统主体已开发完成并投入试点，无外部交付等待期
- 维护成本：不依赖专业算法团队。系统为便携版（整文件夹拷贝即用，自动适配有无显卡），业务人员经约 1 小时培训即可自主完成数据标注、模型重训与版本切换

（四）核心 AI 能力清单
- 多模态识别（图像缺陷检测）：CT 图像缺陷自动定位与分类，单张 ≤300ms（GPU 实测约 50~150ms）
- 数据读取分析：批量检测、缺陷数量统计、Excel 报表导出
- 工作流自动化：上传 → 检测 → 统计 → 报表导出全流程自动完成
- 规划扩展：智能体对话（面向新人的内置使用助手，本地小模型运行，内网环境可用）

（五）硬件与软件明细（均已到位）
- 采购电脑（已购买）：GPU RTX 5060 8GB / CPU i5-10400 级以上 / 内存 ≥32GB / SSD 1TB 以上 / Windows 64bit
- 深度学习框架：PyTorch 2.8.0（CUDA 12.8）+ torchvision 0.23.0
- 目标检测引擎：Ultralytics YOLOv8 v8.4.146（AGPL-3.0 开源协议，内部自用无授权风险；如未来对外商用交付，将采购企业授权或迁移至 Apache-2.0 协议模型）
- 图像处理：OpenCV 4.8.1 + Pillow + NumPy 1.26
- Web 服务端：Flask 3.1（RESTful API，支持文件上传/批量推理/结果打包）
- 数据报表：Pandas 2.3 + OpenPyXL（Excel 导出，含样式格式化）
- 数据标注：X-AnyLabeling（支持 AI 预标注，人工只需修正，标注效率提升 5-10 倍）
- 开发环境：Python 3.10 | Windows

五、预期量化效益（分可量化直接收益+ 间接价值）

（一）降本类
智能穿戴BU：69.4天*4批*500元/人天=13.9万元
马安园区：5500000张*5(秒/张)/3600/8=954天*500元/人天=47.7万
（二）增效类
单张识别耗时从≥5s/张压缩到 300ms/张以内（GPU 实测约 50~150ms/张），效率提升一个数量级；批量推理支持 16 张/批。
（三）风控类
人员疲劳、经验差异容易导致误检、漏检，不同人员判定标准不一致，质量波动大。使用模型辅助判别可固化判定标准、显著降低人为波动，降低质量风险。（上线初期定位为"AI 初筛 + 人工复核"，识别率随样本积累持续提升）
（四）间接收益类
通过项目方式运作，将实际业务部门工具孵化成公司级应用并部署，为AI应用落地提供参考；模型与数据资产未来可推广至所有BU。

九、风险识别与管控措施（以下为IT与业务共同编制）

（一）业务提报风险
1．数据安全风险：敏感数据外泄
管控：已经与IT拉通，使用专门配置的电脑与网卡；系统私有化部署，检测数据不出内网
2．业务适配风险：模型识别准确率不达标
管控：使用标准结果与测试结果匹配计算准确率；建立"漏检/误检样本回收→标注→重训"闭环；上线初期采用 AI 初筛 + 人工复核模式
3．成本超支风险：API 调用量超额产生额外费用
管控：系统本地部署，无 API 调用费用，框架已搭建完毕，无此风险

（二）IT提报风险
1：调试接入风险：新电脑/产线机器环境差异导致无法运行
管控措施：系统已做成便携版，内置完整运行环境，整文件夹拷贝即用；自动适配有无显卡；提供一键环境体检工具
2：文件外发风险：模型权重与检测数据外泄
管控措施：模型与数据均存储于内网专用电脑，系统无外联功能
3：知识产权风险：YOLOv8 为 AGPL-3.0 开源协议
管控措施：内部自用场景不触发协议限制，无风险；如未来对外商用交付，采购 Ultralytics 企业授权，或迁移至 Apache-2.0 协议模型（PP-YOLOE+ / YOLOX 等，精度同级，标注数据可直接复用，迁移成本低）
