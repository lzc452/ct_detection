## ① 裁剪对导出的原图与标注图质量的影响

### 1.1 分对象说清楚：五个「图」不是一回事

「导出的原图与标注图」在系统里对应五个不同的东西，影响程度完全不同：

| 对象 | 是否存在质量变化 | 依据 |
|---|---|---|
| **A. 母本原始图片**（`问题电芯图片汇总/`） | **零变化**。只读，从未写入 | 物化脚本只有 `read_cn()` 读、`write_cn()` 写到 `datasets_v51/`；抽查源文件 mtime 仍是 `2026-08-13 10:19:25`，早于本次全部工作 |
| **B. 训练/评测用的裁剪图**（`datasets_v51/CT_DATASET_V51_ROI/`） | **有，但极小**：仅 q95 JPEG 重编码 | §1.2 实测 |
| **C. 数据集标注 `.txt`** | **零几何误差** | §1.3 |
| **D. 线上导出的标注结果图**（`web/results/result_*.jpg`） | **不受影响**：画完再 1:1 贴回原图 | §1.4 |
| **E. 线上导出的原图副本**（`web/results/orig_*.jpg`） | **不受影响**：仍是上传的原图，PIL q95 保存 | `web/app.py:422-427` |

### 1.2 B 项的量化：裁剪本身无损，损失全部来自重编码

两个关键事实：

1. **裁剪没有重采样**。`core/roi.py:91` 的 `crop_roi()` 就是 `img[y0:y1, x0:x1]` 的纯像素切片，不经过 `cv2.resize`，所以几何上逐像素等于原图——不存在插值模糊、不存在尺度失真。
2. **唯一的损失是写盘时的 JPEG 量化**（`scripts/materialize_roi_dataset.py:43-47`，`q=95`）。

实测（`scripts/analyze_roi_fidelity.py`，各抽 12 张，含标注的优先；结果落盘 `reports/eval/roi_fidelity.json`）：

| 分组 | ROI 尺寸 | PSNR 中位 | SSIM 中位 | MAE | 单点最大误差 | 缺陷框内灰度 std 变化 |
|---|---|---|---|---|---|---|
| 高分辨率组（2129×1198） | 647×991 | **47.00 dB** | 0.98455 | 0.728 / 255 | 9 / 255（3.5%） | 23.20 → 23.21（**+0.05%**，n=15 框）|
| 低分辨率组（1052×585） | 319×484 | **45.39 dB** | 0.97958 | 0.897 / 255 | 9 / 255 | 18.48 → 18.54（**+0.30%**，n=12 框）|

**为什么损失这么小**：三类缺陷都是低频的亮度/暗度斑块（亮斑 16.7px、暗斑 25.1px、损伤条 18.7px 宽），能量集中在低频；JPEG 量化误差集中在高频。所以「缺陷框内灰度标准差」——也就是缺陷本身的可分辨信号强度——几乎没变（+0.05% / +0.30%）。这一点比 PSNR 更能说明问题：PSNR 是全图平均，缺陷区只占 0.01%~0.06% 面积，平均指标会被大面积正常区稀释。

**编码质量是可调的，代价也不高**（同一批 8 张，q95 分组）：

| JPEG 质量 | PSNR 中位 | MAE 中位 | 中位体积 | 相对 q95 体积 |
|---|---|---|---|---|
| 100 | 59.64 dB | 0.071 | 238 KB | +105% |
| 98 | 51.54 dB | 0.392 | 180 KB | +55% |
| **95（当前）** | **47.14 dB** | **0.722** | **116 KB** | 基准 |
| 90 | 45.05 dB | 0.932 | 74 KB | −36% |
| 85 | 44.02 dB | 1.056 | 56 KB | −52% |

结论：q95 已经进入「视觉与训练都无损」区间（>45 dB）。若要把重编码损失彻底从实验里剔除，用 q98 只需多 55% 磁盘（340 MB → 约 530 MB）。**当前结论不依赖这个改动**——因为对比双方（V5 与 V5.1）用的是同一套重编码流程时该误差同向，但 V5 用的是原图、V5.1 用的是 q95 裁剪图，严格说这是两个口径之间一个 47 dB 级别的不对称噪声源。这个不对称**不利于 V5.1**（V5.1 多受一次编码），量级远小于任何被测差异（4% 的 mAP 差异对应的是完全不同的误差量级），可以忽略，但登记在此。

### 1.3 C 项：标注为什么是零误差

`core/roi.py` 的变换是：像素坐标先减去 ROI 左上角，再除以 ROI 的整数宽高做归一化。ROI 边界本身就是整数（`roi_box()` 返回 int），所以没有「半个像素」的偏移问题；YOLO 要求的是归一化浮点，落盘保留 6 位小数。

独立复算验证（不调用被测代码，直接从原始 labelme JSON 重算）：抽 4 张图，`2_0763` 得到 `0.395455 0.235912 0.026886 0.024947`，与数据集里的 `.txt` **6 位小数完全一致**。其余 3 张同样一致。

丢掉框的风险已实测为 0：`materialize_roi_dataset.py --verify-only` 输出「保留框 2503 | 丢弃框(越界) 0 | ROI 有效性失败 0 | 无缺陷图 1649 | 缺失 0」（train 3195 + val 721 = 3916 张，对应清单里除 test 外全部标注框）。

**这里有个必须说清的取舍**：`labelme_boxes_in_roi()` 只保留**完整落在 ROI 内**的框，越界框直接丢弃而不是截断。理由：截断会改变真值框的形状，把一个「部分可见」的缺陷教成「完整缺陷」，污染监督信号。当前数据下 0 个越界框，所以这个取舍没有实际代价；但如果将来标注风格变化（比如跨边界的连续损伤被标成一整条），就会静默丢框——脚本已输出 `n_dropped` 计数，需要人工盯这个数。

### 1.4 D 项：线上标注图不受影响，但要看清实现方式

`web/app.py:203-214`：

```python
roi_drawn = res.plot()          # 在 ROI 图上画（此时仍是 ROI 坐标）
draw = orig_img.copy()
draw[y0:y1, x0:x1] = roi_drawn  # 1:1 贴回原图对应位置
return draw
```

这是关键设计：**不是**把 ROI 图单独导出，也不是把 ROI 图缩放后合成。原图其余 74.9% 像素是 `orig_img.copy()` 的原始值，一个字节都没动；ROI 区域写入的是同一块像素（无缩放、无插值）再叠上标注线。所以导出图与「改造前直接在原图上画」的差别，只有 ROI 区域内的标注线/文字，而这部分本来也画在同样的位置。

顺序约束写在注释里：必须在 `_restore_boxes()` **之前**调用（框还在 ROI 坐标时才和 ROI 图像对齐）。这个顺序被 `scripts/test_infer_roi.py` 的第 1、2 条断言覆盖（断言内容是「draw 的尺寸 == 原图尺寸」）。

### 1.5 真正的影响不在像素，在**视场**

必须把这句话说在前面：**裁剪把 74.9% 的像素永久排除在检测范围外**（ROI 只占原图 25.14% 面积：647×991 / 2129×1198 = 641,177 / 2,550,542）。

- 标注框外包络只占原图面积的 **19.72%**（`docs/preprocess_analysis_20261021.md`，基于 2945 个框）
- 2945 个框的中心全部落在 x ∈ [0.355, 0.595]，ROI 边界取了 x ∈ [0.3209, 0.6248]、y ∈ [0.1181, 0.9446]（2.5% 余量）
- 原图是 16:9 的「界面拼贴」：左侧参数面板、右下角另有一个小视野视图，**那张小视图里没有任何标注框**

所以：如果哪天产线布局变了（比如电芯移到画面另一侧、或者加了新的相机角度），ROI 会静默裁到空白区，模型输出为空且不报错。当前的防线只有一条：`roi_looks_valid()` 用灰度标准差阈值 20.0 判断 ROI 是否「像电芯」，低于阈值会打印警告（`web/app.py:181-185`），但**只警告、不阻断**，且最多打印前 5 次。

这条风险的可信度评级：**高**（机制清楚、无兜底）。建议后续加一条硬闸：连续 N 张 ROI 校验失败就拒绝出结果。

## ③ ROI 画布为什么定 1536

### 3.1 先把「画布」和「缺陷有多大」的关系算清楚

这是第一性的量：**送进网络的图上，缺陷占多少像素**。它由两步缩放决定：

1. 裁剪：ROI 是原图的 `0.3039 × 0.8265` 倍（`core/roi.py:68-69` 的边界），无缩放
2. LetterBox：ROI（647×991，竖长）放进 C×C 方形画布，缩放率 = `min(C/647, C/991) = C/991`（受高度限制）

**所以画布越大，缺陷越大；而且竖长 ROI 放进方形画布会永久浪费 34.7% 的画布面积**（内容宽度只有 0.653C）——这个浪费是 `imgsz` 只能方形造成的，无法回避。

原生缺陷尺寸（`reports/eval/roi_fidelity.json` → `defect_sizes_native.hi`，按真实标注框统计，高分辨率组）：

| 类别 | n | 宽中位 | 高中位 | 面积占比中位 |
|---|---|---|---|---|
| 极片损伤 | 358 | 18.7 px | 65.4 px | 0.056% |
| 暗斑 | 1423 | 25.1 px | 25.0 px | 0.026% |
| **亮斑** | **770** | **16.7 px** | **16.7 px** | **0.011%** |

亮斑是三类里最小、也是 AP 最低（0.487 vs 暗斑 0.533）的那一类，**所以它以约束条件的形式决定了画布下限**。

### 3.3 判定逻辑：四条约束，只有 1536 同时满足

| 约束 | 来源 | 数学形式 | 满足者 |
|---|---|---|---|
| 方形 int、32 对齐 | `trainer.py:340` + 卷积 stride | C % 32 == 0 | 1024…2112 全部 |
| 亮斑 ≥ 1.5× V5 推理尺度（15.1×1.5 = **22.7 px**） | 要给「关不掉的噪声」留足余量；1.5× 是让 mosaic 重新可负担的门槛 | 16.7·C/991 ≥ 22.7 → C ≥ 1347 | 1408 / 1536 / 1792 / 1920 / 2112 |
| 算力 ≤ 2.5 MP（单图推理必须快于 V5 的 13.4 ms） | `V5_80ep_v5test.json:layer1_coco.speed_ms` 合 13.4 ms；1536 实测 11.1 ms | C² ≤ 2.5e6 → C ≤ 1581 | 1024…1536 |
| mosaic 子格内亮斑 ≥ V5 训练尺度（7.5 px） | 见 §4.2，为 V5.2 预留可行性 | 16.7·C/1982 ≥ 7.5 → C ≥ 890 | 全部 |

**交集 = {1536}，唯一解。**

### 3.4 诚实披露：这个唯一解里有多少是判断、多少是实验

- 「1.5×」和「2.5 MP」这两个数**是我定的门槛，不是实验测出来的最优点**。换成 1.3× 与 3.4 MP，答案就变成 1792。门槛的取值直接决定答案，这一点必须承认。
- **没有画布消融实验**。1408 与 1536 之间（亮斑 23.7 vs 25.9 px、算力 1.98 vs 2.36 MP）没有任何实验区分，不能声称 1536 比 1408 好。
- 唯一实测的画布证据是 **A(全图@2112) → B(ROI@1536)** 这一对，它把「裁剪」和「画布 2112→1536」绑在一起，涨了 +0.0554 mAP50-95。**严格说这是两变量对照，不能单独归因给画布。**
- 1792 的推理耗时（约 15 ms）是从 MPI 线性外推的，**未实测**。

**要补齐这个空白，最小代价的实验**：在 V5.2 的权重上固定不训练，只改推理 `imgsz` ∈ {1280, 1408, 1536, 1792}，测 mAP / FP / 耗时。这只能回答「固定权重下的画布敏感性」，仍不等于「最佳训练画布」，但能给出误差上界。若需要真正的训练级消融，每个点约 1.9 h，需要 2 个点（1408、1792）才能判断 1536 是否偏大。

## ④ 恢复正则化后能否优于 V5：预注册 + 第一性拆解

### 4.1 预注册（写在看到结果之前，防止事后编故事）

**实验**：`V52_ROI_1536_REG`，与 V5.1-B **唯一差别**是恢复 V5 的全部增强：

```
数据/画布/优化器/lr0/seed 全部不变（ROI 数据集、1536、AdamW、lr0=1e-3、seed=0）
mosaic 0 → 1.0        close_mosaic 0 → 10
degrees 0 → 5         translate 0 → 0.05
erasing 0 → 0.4       cls_pw 0.5 → 0（回到 V5 设置）
```

这样 V5.2 − V5.1-B 就是**增强的单变量效应**（同一数据、同一画布、同一随机种子）。

**主判据**：冻结 test 676 张，`layer1_coco.mAP50_95`（走 `model.val`，跨模型同口径）。

| 判定 | 阈值 |
|---|---|
| 优于 V5 | mAP50-95 **> 0.4186** |
| 追平但无净收益 | 0.4015 ~ 0.4186（即增益为 0 ~ +0.0171） |
| 不如 V5.1-B | < 0.4015（说明恢复增强有害） |

**辅助判据**（任一不满足都不能称「优于」）：FP/千张 ≤ 88.8、组级漏检 ≤ 26.47%、损伤召回 ≥ 0.5616。

**机制预测（可被证伪，不是结论）**：

| 编号 | 预测 | 若失败说明什么 |
|---|---|---|
| P1 | 增强回补带来 **≥ +0.0171** mAP50-95（V5.1-B 0.4015 → ≥0.4186） | 「增强削减是主因」这个推断错误，需另找原因（如裁剪丢上下文） |
| P2 | 损伤召回从 0.397 回到 **≥ 0.50** | mosaic 帮不了损伤类，「损伤召回塌陷」另有机制（候选：损伤框宽仅 18.7px，mosaic 后仅 14.5px，反而更难） |
| P3 | val/box_loss 的**绝对值**上升（mosaic 抬高难度），但不能用来和 V5.1-B 比间隙 | — |

### 4.2 第一性拆解：需要多少增益才够，物理上够不够

**算账**（全部来自 `reports/eval/*.json`）：

| 量 | 值 | 来源 |
|---|---|---|
| V5.1-B 落后 V5 的量 | 0.4186 − 0.4015 = **0.0171** | 两份报告 `mAP50_95` |
| ROI 在同超参下带来的增益（A→B） | 0.4015 − 0.3461 = **+0.0554** | 同上 |
| 关增强 + 换画布带来的损失（V5→A） | 0.3461 − 0.4186 = **−0.0725** | 同上 |

所以只需补回 **0.0171**（相当于 ROI 已挣到的 +0.0554 的 31%）就能追平。**从算术上完全可能**。

**但物理上有一个硬约束会吃掉一部分收益**：mosaic 把 4 张图拼进一个画布，每张只占 C/2 的格子，缩放率减半。

- V5 训练时：全图 2129×1198 进 960 格 → 缩放 0.451 → 亮斑 **7.5 px**（推理时 15.1 px，训练/推理失配 **2.01×**，这是 V5 的结构性缺陷）
- V5.2 训练时：ROI 647×991 进 768 格 → 缩放 0.775 → 亮斑 **12.9 px**（推理时 25.9 px，失配仍是 2.01×，但**绝对尺度是 V5 训练时的 1.72 倍**，且已接近 V5 推理时的 15.1 px）

这正是 ROI 的价值所在：它把「付 2× 失配」的成本从绝对 7.5 px 抬到 12.9 px。**换句话说，mosaic 在 V5 里是有害的（把亮斑压到 7.5 px 还没钱补），在 V5.2 里才变成可负担的正则化**。这是本次「恢复正则化」假设的物理基础，不是直觉。

**风险面（同样从第一性出发）**：

1. `erasing=0.4` 会随机擦除图块。ultralytics 的随机擦除面积比例下限足以覆盖 16.7px 的亮斑——擦掉就变成「负样本里有缺陷」，会直接压低亮斑召回。V5 有 erasing 0.4 且亮斑召回 0.896，说明不致命，但这是**已知的召回税**。
2. `cls_pw 0.5 → 0` 会让损伤类重新欠采样（损伤仅占框数 484/2945 = 16.4%）。V5.1-B 的 cls_pw 0.5 曾是损伤召回的一个可能助力；本次为了「单变量只动增强」把它也改回 0，代价是**这一项也变了**——严格说 V5.2 vs V5.1-B 是 5 个增强参数 + 1 个损失参数共 6 个变量的变化，不是纯增强单变量。这是本次设计的**已知妥协**：为了让 V5.2 与 V5 的配置完全一致（差在数据与画布），牺牲了与 V5.1-B 的严格单变量性。
3. 训练集只有 3195 张 / 2503 个框。mosaic 会把它组合成 4× 的样本量，缓解数据不足——这是支持假设的一面。
