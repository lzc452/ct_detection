### D-001 生产模型保持 V5（全图 @1920），不切换 V5.2
- **日期**：2026-10-22 · **状态**：生效
- **背景**：V5.2 四条预注册判据全负（mAP 0.3977 < 0.4186、FP 131.7 > 88.8、组漏检 28.8% > 26.47%、损伤召回 0.438 < 0.5616），只有推理速度赢（10.4 ms vs 13.4 ms）
- **备选**：① 切 V5.2 换速度；② 保持 V5 等下一轮
- **结论**：保持 V5。误报与漏检是产线成本的主要来源，速度不是当前瓶颈
- **代价**：单张 13.4 ms、训练 3.32 h，都比 V5.2 高 22%~35%
- **复核触发条件**：产线节拍成为硬约束（单张可用时延 < 12 ms），或损伤类问题被单独解决后 V5.2 的短板只剩速度

### D-002 用冻结 test 清单当唯一考卷，按电芯/批次分组划分
- **日期**：2026-10-21 · **状态**：生效
- **背景**：V3/V4 时代 test 有 93.9% 的图出现在训练集里，指标虚高 0.13~0.15
- **结论**：`reports/splits/v5_split_manifest.csv` 冻结（4592 张：train 3195 / val 721 / test 676），**同电芯不跨集**；此后所有模型在这同一份清单上评测
- **代价**：不能再用旧模型的"高分"做宣传口径；新旧数字不可直接比较
- **复核触发条件**：数据量翻倍或产线新增机型，需要重新划分（届时旧清单归档，不覆盖）

### D-003 判据必须预注册，写在训练启动之前
- **日期**：2026-10-22 · **状态**：生效
- **背景**：此前存在"先看结果再定标准"的倾向，导致 V5.1 时代两条结论事后被推翻
- **结论**：每次正式实验前，在文档里写死判据门槛 + 可证伪预测；训练结束后按预注册口径判定，**不做结果回填式解释**。模板见 `docs/v51_defense_qa_20261022.md` §4.1
- **代价**：多花 20 分钟写预注册；实验失败时无法"另找一个指标宣布成功"
- **复核触发条件**：无（这是纪律，不是技术选择）

### D-004 权重不入库，只存路径 + md5
- **日期**：2026-10-21 · **状态**：生效
- **背景**：`*.pt` 每个几十 MB，进 git 会撑爆仓库
- **结论**：`experiments/<run>/weights.txt` 记录原始路径与 md5；`*.pt` 由 `.gitignore` 拦截
- **代价**：clone 后拿不到历史权重，只能靠 md5 校验本地文件是否被替换
- **复核触发条件**：需要长期复现某个版本时，改用对象存储/LFS

### D-005 评测分三层，选型只看层 2/3
- **日期**：2026-10-22 · **状态**：生效
- **背景**：`model.val`（层 1）与产线 `predict`（层 2/3）口径不同（含 `scaleup=False` 的差异），两者数字不能混用
- **结论**：
  - 层 1 = COCO mAP，走 `model.val`，**只用于跨模型横向比**
  - 层 2 = 工作点 P/R、FP/千张，层 3 = 组级漏检，走 `predict`，**用于选型**
  - 电芯级漏检索样 n=10，**不用于决策**
- **代价**：每次评测要跑两套流程
- **复核触发条件**：产线改用 `val` 口径，或 ultralytics 修正 `scaleup` 默认值

### D-006 暂停"纯 ROI 裁剪"路线，不再调 ROI 画布与增强
- **日期**：2026-10-22 · **状态**：生效
- **背景**：画布（1536）与增强（mosaic/degrees/erasing）两条都已做单因素否定（F-005、F-013）。继续调这两项属于在已关的门上继续推
- **结论**：ROI 路线若重启，必须改成**带余量裁剪**（`margin = max(k·长边, c)`），并按分辨率分桶
- **代价**：暂时放弃 −22% 的推理速度收益
- **复核触发条件**：带余量裁剪实验完成（见 `docs/v6_optimization_plan_20261023.md` P0-2）

### D-007 不改 site-packages，口径差异用对照脚本量化
- **日期**：2026-10-22 · **状态**：生效
- **背景**：`dataset.py:319` 的 `scaleup=False` 是治标不治本的口径问题
- **结论**：不 patch 库。用 `scripts/eval_scaleup.py` 跑对照，把影响量化后登记（V5 −0.0108、V5.2 +0.0015，≤1.5σ，排序不变）
- **代价**：层 1 的绝对值始终带一个已知偏差
- **复核触发条件**：升级 ultralytics 版本时重新确认该行为是否已修

### D-008 训练结束自动归档，人工结论写在独立区块
- **日期**：2026-10-22 · **状态**：生效
- **背景**：`runs/` 是 ultralytics 自动产物，缺少"这次测出了什么、结论是什么"
- **结论**：`scripts/train_run.py` 结束时自动调 `archive_experiment.py`，生成 `experiments/<run>/`。`04_report.md` 的 1–4 节由脚本按真实文件重算，第 5 节人工结论包在 `ARCHIVE-NOTES` 标记里，重跑不覆盖
- **代价**：每轮训练多几十秒复制产物
- **复核触发条件**：无

### D-009 ROI 余量 k 走「模块级单源」，不给单个函数加参数
- **日期**：2026-10-23 · **状态**：生效
- **背景**：带余量裁剪需要同时改「裁图窗口」和「GT 变换窗口」。若给 crop_roi 加 k、给 labelme_boxes_in_roi 加 k，两处分开传参，任何一处漏传就出现「图按一种裁法、标签按另一种算」，指标全错且不报错（L-012 同类）
- **备选**：（未记录）
- **结论**：在 core/roi.py 设模块级 _MARGIN_K，由 set_margin_k 显式设置；roi_box 保持原样不动，新增 active_box 作为唯一读取入口；crop_roi 与所有 GT 变换都走 active_box。k=0 时 active_box 与 roi_box 逐位相同，历史结果可复现
- **代价**：（未记录）
- **复核触发条件**：若出现「同一进程内需要同时评估两个不同 k 的模型」，改用显式传参 + 断言，不要靠全局

### D-010 终止 ROI 裁剪路线，生产模型保持 V5 全图@1920
- **日期**：2026-10-23 · **状态**：生效
- **背景**：V5.1~V5.3 连续三轮用不同裁剪/画布组合尝试用 ROI 放大换取小目标分辨率。V5.1-A 因过拟合被推翻；V5.2 四项判据全败；V5.3 加余量后追回到 mAP 0.4155（V5 0.4186）、FP 110.9（V5 88.8）、损伤 R 0.466（V5 0.562），仍全败
- **备选**：（未记录）
- **结论**：ROI 路线停止，不再投入。判据：损伤 AP 在四种非泄漏数据表示下全落在 0.16~0.24（全图@1920 0.2363 / 全图@2112 0.1647 / ROI@1536 k=0 0.1813 / k=1.5 0.1880），对画布、缩放率、视野宽窄均无单调关系；而余量裁剪把暗斑完整救回（+0.0385，与 V5 打平）却只给损伤 +0.0067，敏感度为暗斑的 1/6
- **代价**：（未记录）
- **复核触发条件**：出现以下任一情况可重启评估：(a) 损伤标注审计显示标注间 IoU 中位>=0.75 且损伤 AP 带被证明确由数据量造成、扩充损伤样本后带整体上移；(b) 引入切片级联（P2-1）等按类别分路的架构，使损伤不再与暗斑/亮斑共用同一输入表示；(c) 相机/工位变更导致原生分辨率或 ROI 定义改变
